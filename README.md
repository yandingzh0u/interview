# 面试题库

本地运行的面试题背题工具。自己录题，按固定答题骨架分段，空格逐段揭示答案。

## 运行

Windows 双击 **`启动.bat`**，浏览器会自动打开 `http://127.0.0.1:7788`。

或者命令行：

```bash
node server.mjs
```

需要 Node.js 18+。零依赖，不用 `npm install`。关闭那个黑窗口就是停止服务，数据已经存盘。

## 怎么用

1. 题库页 → 「新建题目」，或者「批量导入」粘一段
2. 选**答题类型**（7 套平级固定骨架，点一下自动生成对应分段框）
3. 按骨架分段填答案，每段一个输入框
4. 背诵页按空格逐段揭示

键盘：

| 键 | 作用 |
|---|---|
| `空格` | 展开下一段 |
| `→` | 下一题 |
| `←` | 上一题（直接全展开） |
| `N` | 展开 / 收起备注 |

## 七套固定答题骨架

每道题只选一个答题类型，取消一级/二级两层。**每套骨架的每一段都必填，不留空**；前端不做内容判断，你怎么写就怎么显示。

| 答题类型 | 固定分段 | 适合什么问题 | 缺某段时的标准写法 |
|---|---|---|---|
| **概念与原理** | `核心说明` | 是什么、作用、分类/组成、底层结构、监控指标、复杂度 | 1 段，直接填 |
| **工作流程** | `具体流程` | 执行链路、握手挥手、持久化/主从/扩容/GC/事件循环 | 1 段，直接填 |
| **判断与原因** | `判断与原因` | 为什么、一定吗/会不会/靠谱吗、有什么影响（第一句先拍板/破题，紧接讲机制） | 1 段，直接填 |
| **对比与选型** | `核心差异` → `怎么选` | 有什么区别、优劣势、技术选型、什么场景选哪个 | 只有区别没选型 → 段 2 填 `该题只有区别，没有「怎么选」`<br>只问怎么选没固定对比项 → 段 1 填 `该题只问怎么选，无需单独讲差异` |
| **方案与治理** | `问题/原因` → `核心方案` | 如何设计、怎么规避/防坑、怎么排查/处理、通用优化、代码做法 | 题目已给定问题 → 段 1 填 `题目已经给了，该部分无需说明` |
| **效果评估** | `评测集` → `评测指标` → `结果分析` | AI / RAG 离线评测 | 3 段，全部填写 |
| **项目复盘** | `基线` → `瓶颈` → `改进` → `对照验证` | 简历项目里的真实性能调优经历 | 4 段，全部填写 |

## 一道题里问了不止一件事，怎么办

分三种：

| 情况 | 例子 | 处理 |
|---|---|---|
| 两个问题能独立提问、独立回答 | 「`sort()` 和 `sorted()` 有什么区别？如何按多个字段排序？」 | **拆成两张题卡**，各自套对应骨架 |
| 几个问法共同构成一个考察目标 | 「相比微调，RAG 解决了什么？各自优劣势？」 | **保留一道题**，挂 `对比与选型` |
| 第二问是面试官可能继续深入的 | 「为什么需要三次？两次不行吗？」 | **放进追问** |

## 备注

每道题都可以单独写一条备注，用来记「没懂的地方、自己的理解、面试时想补一句的话」。它不会混进答案里。

- 背诵页在步骤下方有折叠的 `▸ 备注` 一行，点开就看，按 `N` 也能展开/收起
- 换题时自动收起，不会泄底
- 题库列表里，有备注的题目会多一个「备注」小标记；搜索也会搜备注内容

## 数据

| 文件 | 作用 |
|---|---|
| `data/bank.jsonl` | 题库，一行一道题 |
| `data/frameworks.json` | 骨架配置，改这里全库生效 |
| `data/history.jsonl` | 每次增删改的流水，可回放（不进版本库） |
| `data/backups/` | 每次覆盖前的时间戳快照（不进版本库） |

备份就是复制 `bank.jsonl`。它也可以直接用记事本改，改完刷新页面就生效——服务端会比对文件修改时间自动重新载入；某一行写坏了只会跳过那一行，不会毁掉整个题库。

### 改类型名字不会把老题挂空

改名或合并的历史写在 `data/frameworks.json` 顶层的 `aliases` 里：

```json
"aliases": { "原因机制": "判断与原因" }
```

- 服务端每次载入题库按 `aliases` 对齐一遍，老题自动落到新名字上
- 写入时也会校验：名字对不上任何一项就**拒绝保存**，并告诉你可以选哪些

## 批量导入格式

```
Q: 如何规避 RAG 系统中大模型的幻觉？
CAT: 方案与治理
SEG: RAG 里的幻觉主要有两类：一是检索没召回，二是召回了模型自行推断。
SEG: 一是在 Rerank 后卡阈值，二是 Prompt 硬约束，三是要求带引用编号，四是生成后核查。
FU: 怎么量化幻觉率？ | 用大模型把回答拆成陈述句，逐句对照原文核验（Faithfulness）
NOTE: 这里写自己的理解，不会算进答案，可以接着写多行。
```

- `Q` 必填，`CAT` 建议填（填 7 套答题类型之一，也兼容旧 `一级 / 二级` 写法）
- `SEG` 一行一段，对应骨架的每一步
- `FU` 是追问，`|` 后面是答题提示
- `NOTE` 是备注，只给自己看
- 重复的题会自动跳过

## 技术

只用 Node 内置模块，没有第三方依赖。Markdown 渲染和代码高亮用 `vendor/` 里的 marked + highlight.js，已经本地化，断网也能跑。

写入采用 `.tmp` → `rename` 的原子方式，写到一半断电不会产生半截文件。
