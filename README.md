# 面试题库

本地运行的面试题背题工具。自己录题，按答题骨架分段，空格逐段揭示答案。

## 运行

Windows 双击 **`启动.bat`**，浏览器会自动打开 `http://127.0.0.1:7788`。

或者命令行：

```bash
node server.mjs
```

需要 Node.js 18+。零依赖，不用 `npm install`。关闭那个黑窗口就是停止服务，数据已经存盘。

## 怎么用

1. 题库页 → 「新建题目」，或者「批量导入」粘一段
2. 选**一级 Tag**（决定按什么顺序想）和**二级问法**（决定每一步叫什么）
3. 按骨架分段填答案，每段一个输入框
4. 背诵页按空格逐段揭示

键盘：

| 键 | 作用 |
|---|---|
| `空格` | 展开下一段 |
| `→` | 下一题 |
| `←` | 上一题（直接全展开） |

## 五个一级 Tag 与十六套答题方法

一级 Tag 只是**思路**（怎么想），二级 Tag 才是**答题步骤**（怎么讲）。两者不按下标强行配对。

| 一级 Tag | 思路 | 二级 Tag 与固定答法 |
|---|---|---|
| 解释原理 | 下判断 → 拆要点 → 讲关系 → 收口 | 是什么：定义 → 核心含义<br>为什么这样：结论 → 原因 → 机制<br>有哪些：分类依据 → 主要类别及特点<br>怎么工作：总览 → 分阶段展开 |
| 对比选型 | 立维度 → 比差异 → 算代价 → 给条件 | 有什么区别：比较维度 → 核心差异 → 结论<br>为什么选A：原方案缺口 → A 的优势 → 代价<br>怎么选：判断条件 → 场景匹配 → 选择结论 |
| 设计实现 | 定边界 → 拆结构 → 讲流程 → 防异常 → 做验证 | 如何设计：目标约束 → 模块 → 流程 → 异常 → 验证<br>怎么实现：输入输出 → 具体实现 → 边界处理<br>怎么落地：业务环境 → 接入部署 → 监控验证 |
| 排障治理 | 看现象 → 分原因 → 找证据 → 做修复 → 防复发 | 为什么出错：现象 → 原因 → 触发机制<br>怎么定位：现象 → 排查路径 → 证据 → 根因<br>怎么处理：根因 → 修复措施 → 验证与预防 |
| 评测优化 | 立基线 → 定指标 → 做实验 → 看结果 → 讲取舍 | 怎么评估：目标 → 指标与数据 → 评估方法 → 结论<br>指标怎么设计：衡量目标 → 定义与计算 → 阈值和边界<br>如何优化：基线 → 瓶颈 → 改进 → 对照验证 |

**同一类题共用一套方法，只换知识内容。** 比如「怎么工作」永远是「总览 → 分阶段展开」：RAG 讲离线/在线两个阶段，Redis 讲建立复制/全量同步/增量同步——阶段名是内容，不是新模板。

页面上同时显示两行：

```
思路  下判断 → 拆要点 → 讲关系 → 收口
步骤  1 总览 → 2 分阶段展开
```

**不要求填满。** 只填要讲的段，空着的直接跳过。方法段数变少时，旧答案不会被截断，多出来的段落会显示成「补充 N」，可以并进去或删掉。

## 数据

| 文件 | 作用 |
|---|---|
| `data/bank.jsonl` | 题库，一行一道题 |
| `data/frameworks.json` | 骨架配置，改这里全库生效 |

备份就是复制 `bank.jsonl`。它也可以直接用记事本改，改完刷新页面就生效——服务端会比对文件修改时间自动重新载入；某一行写坏了只会跳过那一行，不会毁掉整个题库。

## 批量导入格式

```
Q: Agent 的上下文工程怎么设计？
CAT: 设计实现 / 如何设计
SEG: 先明确任务类型、上下文窗口和延迟预算。
SEG: 按系统指令、任务状态、历史消息、工具结果四块装配。
SEG: 每轮按当前任务重新装配模型输入。
SEG: 超长时压缩历史，保留必要状态。
SEG: 用任务完成率和上下文成本验证。
FU: 压缩会不会丢关键信息？ | 看任务成功率，不看压缩率
```

- `Q` 必填，`CAT` 建议填
- `SEG` 一行一段，对应骨架的每一步，可以以后再补
- `FU` 是追问，`|` 后面是答题提示
- 重复的题会自动跳过

## 技术

只用 Node 内置模块，没有第三方依赖。Markdown 渲染和代码高亮用 `vendor/` 里的 marked + highlight.js，已经本地化，断网也能跑。

写入采用 `.tmp` → `rename` 的原子方式，写到一半断电不会产生半截文件。
